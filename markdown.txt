# Antigravity Instruction File: Mobile SOAR Phishing Pipeline

## Primary Directives
You are an expert mobile developer and cybersecurity architect. Your task is to build a highly optimized, cross-platform (iOS and Android) mobile client for a 3-tiered Security Orchestration, Automation, and Response (SOAR) pipeline. The core mandate is zero-bloat: the application must be ultra-lightweight and maintain optimal framerates on mid-range devices.

## Tech Stack & Architecture
*   **Mobile Frontend:** Use a lightweight compiled framework. Avoid heavy third-party UI libraries in favor of custom, minimal widgets.
*   **Backend Integration:** The client will interface directly with a Python (FastAPI) backend that handles the deep learning detection models and sandbox orchestration. 
*   **Performance Optimization:** When parsing massive, real-time Indicator of Compromise (IOC) datasets from the peer network, bypass heavy garbage collection by utilizing native C structures via Foreign Function Interface (FFI).
*   **Asset Management:** Do not bundle local image files. Rely on lightweight SVG rendering and fetch dynamic resources asynchronously.

## Feature Implementation
1.  **Tier 1 Dashboard (Real-Time Triage):** Implement a low-latency WebSockets connection to stream live phishing blocks and peer network updates without stalling the main UI thread.
2.  **Tier 2 Alerts (Dynamic Analysis):** Integrate native push notifications to alert the human analyst when the automated sandbox has successfully detonated a suspicious payload.
3.  **Tier 3 Reporting (Law Enforcement Escalation):** Build a minimal, fast-loading form that fetches the generated CERT-In compliant JSON/PDF report, featuring a single, secure action button to submit the intelligence package.

## Documentation & Workflow Constraints
*   **No Unnecessary Dependencies:** Before modifying configuration files (like `pubspec.yaml` or `package.json`), pause and evaluate if the required feature can be built natively. 
*   **Self-Documenting Code:** Explain each new module as it is built, note exactly why an architectural decision was made, and automatically update the `README.md` whenever the directory structure changes.
*   **Initialization:** Start by generating the minimal project scaffolding. Output the estimated bundle size and confirm it remains strictly under 15MB before proceeding to UI development.
